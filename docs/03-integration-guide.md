# راهنمای اتصال فرانت‌اند و بک‌اند (Integration Guide)

این سند شامل جزئیات نحوه اتصال بخش فرانت‌اند (Next.js) به بک‌اند (Express/Prisma) و تنظیمات دیتابیس ابری است.

## ۱. نمای کلی

| بخش                         | پورت   | مسیر در مخزن             |
| --------------------------- | ------ | ------------------------ |
| فرانت‌اند (Next.js)         | `3000` | `frontend/frontend`      |
| بک‌اند (Express)            | `4000` | `backend`                |
| دیتابیس (PostgreSQL / Neon) | —      | ابری، یا لوکال با Docker |

مرورگر مستقیماً به بک‌اند درخواست می‌زند (فراخوانی با `fetch` از کامپوننت‌های کلاینت). پس بک‌اند باید CORS را برای مبدأ فرانت‌اند باز کند.

## ۲. تنظیمات دیتابیس ابری (Neon)

برای جلوگیری از وابستگی به دیتابیس لوکال، از دیتابیس PostgreSQL ابری (Neon) استفاده شده است.

- **محل قرارگیری آدرس:** فایل `.env` در پوشه `backend`
- **متغیر:** `DATABASE_URL` (شامل آدرس اتصال به Neon و پسورد)
- **وضعیت:** دیتابیس به صورت خودکار توسط Prisma مدیریت می‌شود و داده‌ها پایدار (Persistent) هستند.

نمونه‌ی فایل `backend/.env`:

```env
DATABASE_URL="postgresql://USER:PASSWORD@HOST/DB_NAME?sslmode=require"
PORT=4000
FRONTEND_URL=http://localhost:3000
```

> **امنیت:** فایل `.env` شامل پسورد دیتابیس است و نباید در گیت کامیت شود. آدرس واقعی اتصال را فقط بین اعضای تیم و به‌صورت خصوصی به اشتراک بگذارید.

### اجرای مایگریشن

پس از تنظیم `DATABASE_URL`، جدول‌ها را بسازید:

```bash
cd backend
npx prisma migrate dev     # محیط توسعه
npx prisma migrate deploy  # محیط‌هایی که فقط باید مایگریشن‌های موجود اعمال شوند
```

برای مشاهده‌ی داده‌ها در مرورگر:

```bash
npm run db:studio
```

> **نسخه‌ی Prisma:** پروژه روی Prisma **۶** قفل شده است. نصب نسخه‌ی ۸ در اسپرینت اول مشکل ایجاد کرد و به نسخه‌ی ۶ برگشتیم؛ نسخه‌ی پکیج‌های `prisma` و `@prisma/client` را بدون هماهنگی تیم ارتقا ندهید.

## ۳. تنظیمات CORS در بک‌اند

برای اینکه فرانت‌اند (که روی پورت ۳۰۰۰ اجرا می‌شود) بتواند به بک‌اند (که روی پورت ۴۰۰۰ است) متصل شود، تنظیمات CORS در فایل `backend/src/app.ts` به صورت زیر پیاده‌سازی شده است:

```typescript
app.use(cors({ origin: process.env.FRONTEND_URL || "http://localhost:3000" }));
```

اگر فرانت‌اند را روی آدرس یا پورت دیگری اجرا می‌کنید (یا پس از دیپلوی)، مقدار `FRONTEND_URL` را در `.env` بک‌اند تغییر دهید. در غیر این صورت مرورگر درخواست‌ها را به‌خاطر CORS مسدود می‌کند.

## ۴. تنظیمات اتصال در فرانت‌اند

لایه‌ی ارتباط با API در `frontend/frontend/lib/api.ts` قرار دارد و سه تابع دارد:

| تابع                                  | درخواست                       |
| ------------------------------------- | ----------------------------- |
| `getTasks()`                          | `GET /api/tasks`              |
| `createTask(title, description?)`     | `POST /api/tasks`             |
| `updateTaskStatus(taskId, newStatus)` | `PATCH /api/tasks/:id/status` |

آدرس بک‌اند از متغیر محیطی `NEXT_PUBLIC_API_URL` خوانده می‌شود (آدرس سرور، بدون `/api/tasks` و بدون اسلش پایانی). اگر تنظیم نشود، پیش‌فرض `http://localhost:4000` است:

```typescript
const API_URL = (
  process.env.NEXT_PUBLIC_API_URL ?? "http://localhost:4000"
).replace(/\/+$/, "");
const API_BASE_URL = `${API_URL}/api/tasks`;
```

برای تغییر آدرس، فایل `frontend/frontend/.env.local` را بسازید (نمونه: `.env.example`):

```env
NEXT_PUBLIC_API_URL=https://api.example.com
```

> **توجه:** متغیرهای `NEXT_PUBLIC_*` هنگام اجرای dev/build داخل کد قرار می‌گیرند؛ بعد از تغییر آن‌ها سرور فرانت‌اند را ری‌استارت کنید.

انواع داده‌ی `Task`، محدودیت‌های اعتبارسنجی (`TASK_LIMITS`) و کدهای خطا (`ERROR_CODES`) در `frontend/frontend/lib/types.ts` تعریف شده‌اند و باید همیشه با [قرارداد API](./01-api-contract.md) یکسان بمانند.

## ۵. مدیریت داده با TanStack Query

- لیست وظایف با کلید `['tasks']` کش می‌شود (`TaskList`).
- پس از **ثبت موفق** وظیفه‌ی جدید، `invalidateQueries({ queryKey: ['tasks'] })` فراخوانی می‌شود تا لیست دوباره از سرور خوانده شود و فرم پاک شود (`AddTaskForm`).
- پس از **تغییر وضعیت**، پاسخ سرور مستقیماً با `setQueryData` در کش جایگزین می‌شود و درخواست اضافه‌ای زده نمی‌شود.
- تا زمانی که یک تغییر وضعیت در جریان است، دکمه‌های وضعیت غیرفعال می‌شوند.

## ۶. جریان مدیریت خطا

۱. فرانت‌اند ابتدا ورودی را در سمت کلاینت بررسی می‌کند (عنوان خالی، عنوان بیش از ۱۰۰ و توضیحات بیش از ۵۰۰ کاراکتر) و در صورت خطا بدون ارسال درخواست، پیام را نشان می‌دهد.
۲. اگر سرور خطا برگرداند، تابع API بدنه‌ی خطا را به شکل `{ response: { data: { error: "CODE" } } }` پرتاب می‌کند.
۳. `AddTaskForm` مقدار `error` را می‌خواند و پیام ترجمه‌شده را از `errors.<CODE>` در فایل‌های `messages/fa.json` و `messages/en.json` برمی‌دارد.
۴. اگر کد در فایل‌های ترجمه نباشد، پیام `errors.UNKNOWN` نمایش داده می‌شود.

> **قاعده:** هر کد خطای جدیدِ بک‌اند باید همزمان در `docs/02-error-codes.md`، `lib/types.ts` و هر دو فایل ترجمه (`messages/fa.json` و `messages/en.json`) اضافه شود.

خطای تغییر وضعیت (مثلاً `TASK_NOT_FOUND`) بالای جدول وظایف در `TaskList` نمایش داده می‌شود؛ در صورت `TASK_NOT_FOUND` لیست هم دوباره از سرور خوانده می‌شود.

## ۷. چندزبانگی (i18n)

- کتابخانه: `next-intl`، با زبان‌های `fa` (پیش‌فرض) و `en`
- آدرس صفحه‌ها با پیشوند زبان است: `/fa` و `/en`
- ترجمه‌ها در `frontend/frontend/messages/`
- جهت صفحه (`rtl` برای فارسی) و فونت در `app/[locale]/layout.tsx` و `globals.css` تنظیم می‌شود
- متن عنوان و توضیحات وظیفه‌ها با `dir="auto"` نمایش داده می‌شود تا متن فارسی و انگلیسی هر کدام جهت درست خود را داشته باشند
- فرانت‌اند تنها متن‌های رابط کاربری را ترجمه می‌کند؛ بک‌اند هیچ متن زبان‌دار برنمی‌گرداند

## ۸. راه‌اندازی کامل (قدم‌به‌قدم)

۱. مخزن را کلون کنید.
۲. فایل `backend/.env` را مطابق بخش ۲ بسازید.
۳. بک‌اند را اجرا کنید:

```bash
cd backend
npm install
npx prisma migrate dev
npm run dev
```

۴. در ترمینال دیگر، فرانت‌اند را اجرا کنید:

```bash
cd frontend/frontend
npm install
npm run dev
```

۵. آدرس `http://localhost:3000` را باز کنید.

یا با Docker (جزئیات در README):

```bash
docker compose up
```

## ۹. بررسی صحت اتصال

۱. `http://localhost:4000/health` باید `{"status":"ok"}` برگرداند.
۲. در صفحه‌ی اصلی یک وظیفه ثبت کنید (یک‌بار فارسی و یک‌بار انگلیسی)؛ باید در جدول ظاهر شود.
۳. صفحه را رفرش کنید؛ وظیفه باید باقی بماند (نشانه‌ی ذخیره در دیتابیس).
۴. روی برچسب وضعیت کلیک کنید؛ وضعیت باید تغییر کند و پس از رفرش حفظ شود.
۵. با عنوان خالی ثبت کنید؛ باید پیام خطای ترجمه‌شده نمایش داده شود.
۶. جدول `Task` را در Prisma Studio (`npm run db:studio`) یا پنل Neon ببینید.

## ۱۰. مشکلات رایج

| مشکل                               | علت و راه‌حل                                                                                                                |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| خطای CORS در کنسول مرورگر          | مقدار `FRONTEND_URL` در `backend/.env` با آدرس واقعی فرانت‌اند یکی نیست                                                     |
| پیام «خطا در دریافت وظایف» در صفحه | بک‌اند اجرا نیست، یا `NEXT_PUBLIC_API_URL` اشتباه است (پس از تغییر، سرور فرانت‌اند را ری‌استارت کنید)                       |
| خطای اتصال Prisma / `DATABASE_URL` | فایل `.env` وجود ندارد یا آدرس نادرست است؛ برای Neon حتماً `sslmode=require` را بررسی کنید                                  |
| خطای Hydration در Next.js          | محتوای تصادفی یا وابسته به مرورگر نباید در رندر سمت سرور تولید شود (در `NeonStarRain` ستاره‌ها فقط در کلاینت ساخته می‌شوند) |
| خطاهای عجیب پس از نصب Prisma       | نسخه‌ی پکیج‌ها باید ۶ باشد (بخش ۲)                                                                                          |
