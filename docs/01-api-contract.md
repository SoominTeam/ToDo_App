# قرارداد API (API Contract)

این سند شامل مشخصات دقیق endpoint ها، ساختار داده‌ها و قوانین اعتبارسنجی برای اتصال فرانت‌اند و بک‌اند است. فهرست کامل کدهای خطا در [02-error-codes.md](./02-error-codes.md) آمده است.

## قواعد کلی

- **آدرس پایه:** `http://localhost:4000`
- **فرمت داده:** همه‌ی درخواست‌ها و پاسخ‌ها JSON هستند. درخواست‌های دارای بدنه باید هدر `Content-Type: application/json` داشته باشند.
- **فرمت خطا:** همه‌ی خطاها با این ساختار برمی‌گردند. سرور مستقل از زبان است و فقط کد خطا می‌فرستد، ترجمه در فرانت‌اند انجام می‌شود.
  ```json
  { "error": "TITLE_REQUIRED" }
  ```
- **زمان:** مقدار `createdAt` به‌صورت رشته‌ی ISO 8601 و در UTC است.

## مدل داده: Task

| فیلد          | نوع                             | توضیح                                                                       |
| ------------- | ------------------------------- | --------------------------------------------------------------------------- |
| `id`          | `number`                        | شناسه‌ی خودکار و یکتا                                                       |
| `title`       | `string`                        | عنوان وظیفه (۱ تا ۱۰۰ کاراکتر پس از trim)                                   |
| `description` | `string \| null`                | توضیحات (حداکثر ۵۰۰ کاراکتر). اگر ارسال نشود، رشته‌ی خالی `""` ذخیره می‌شود |
| `status`      | `"TODO" \| "DONE" \| "EXPIRED"` | وضعیت وظیفه. مقدار پیش‌فرض: `TODO`                                          |
| `createdAt`   | `string`                        | زمان ایجاد (ISO 8601)                                                       |

نمونه:

```json
{
  "id": 1,
  "title": "خرید نان",
  "description": "نان سنگک",
  "status": "TODO",
  "createdAt": "2026-11-06T12:00:00.000Z"
}
```

## Endpoints

### ۱. بررسی سلامت سرور (Health Check)

**آدرس:** `GET /health`
**توضیحات:** بررسی وضعیت سرور.

**پاسخ موفق (200 OK):**

```json
{ "status": "ok" }
```

---

### ۲. دریافت لیست وظایف

**آدرس:** `GET /api/tasks`
**توضیحات:** همه‌ی وظایف را برمی‌گرداند، مرتب‌شده از **جدیدترین به قدیمی‌ترین** (بر اساس `createdAt`). صفحه‌بندی (pagination) ندارد.

**پاسخ موفق (200 OK):** آرایه‌ای از `Task`. اگر وظیفه‌ای وجود نداشته باشد، آرایه‌ی خالی برمی‌گردد.

```json
[
  {
    "id": 2,
    "title": "Buy milk",
    "description": "",
    "status": "TODO",
    "createdAt": "2026-11-06T12:30:00.000Z"
  },
  {
    "id": 1,
    "title": "خرید نان",
    "description": "نان سنگک",
    "status": "DONE",
    "createdAt": "2026-11-06T12:00:00.000Z"
  }
]
```

**خطاهای ممکن:** `500 SERVER_ERROR`

---

### ۳. ثبت وظیفه‌ی جدید

**آدرس:** `POST /api/tasks`
**توضیحات:** یک وظیفه‌ی جدید با وضعیت `TODO` ایجاد می‌کند.

**بدنه‌ی درخواست:**

| فیلد          | نوع      | الزامی | قوانین                                          |
| ------------- | -------- | ------ | ----------------------------------------------- |
| `title`       | `string` | بله    | پس از trim نباید خالی باشد و حداکثر ۱۰۰ کاراکتر |
| `description` | `string` | خیر    | حداکثر ۵۰۰ کاراکتر. مقدار پیش‌فرض `""`          |

```json
{ "title": "خرید نان", "description": "نان سنگک" }
```

**پاسخ موفق (201 Created):** وظیفه‌ی ساخته‌شده (`Task`).

```json
{
  "id": 1,
  "title": "خرید نان",
  "description": "نان سنگک",
  "status": "TODO",
  "createdAt": "2026-11-06T12:00:00.000Z"
}
```

**خطاهای ممکن:**

| کد HTTP | کد خطا           | شرایط                                                                                    |
| ------- | ---------------- | ---------------------------------------------------------------------------------------- |
| 400     | `TITLE_REQUIRED` | `title` ارسال نشده، خالی یا فقط فاصله است                                                |
| 400     | `TITLE_TOO_LONG` | `title` پس از trim بیش از ۱۰۰ کاراکتر است                                                |
| 400     | `INVALID_INPUT`  | نوع داده نادرست (مثلاً `title` عدد باشد)، `description` بیش از ۵۰۰ کاراکتر، یا JSON خراب |
| 500     | `SERVER_ERROR`   | خطای غیرمنتظره                                                                           |

**نکات:**

- اگر چند خطای اعتبارسنجی همزمان وجود داشته باشد، فقط **اولین** خطا برگردانده می‌شود.
- `title` قبل از ذخیره trim می‌شود.

---

### ۴. تغییر وضعیت وظیفه

**آدرس:** `PATCH /api/tasks/:id/status`
**توضیحات:** وضعیت یک وظیفه را تغییر می‌دهد.

**پارامتر مسیر:**

| پارامتر | نوع      | توضیح         |
| ------- | -------- | ------------- |
| `id`    | `number` | شناسه‌ی وظیفه |

**بدنه‌ی درخواست:**

| فیلد     | نوع      | الزامی | مقادیر مجاز               |
| -------- | -------- | ------ | ------------------------- |
| `status` | `string` | بله    | `TODO`، `DONE`، `EXPIRED` |

```json
{ "status": "DONE" }
```

**پاسخ موفق (200 OK):** وظیفه‌ی به‌روزشده (`Task`).

```json
{
  "id": 1,
  "title": "خرید نان",
  "description": "نان سنگک",
  "status": "DONE",
  "createdAt": "2026-11-06T12:00:00.000Z"
}
```

**خطاهای ممکن:**

| کد HTTP | کد خطا           | شرایط                                                                                                                 |
| ------- | ---------------- | --------------------------------------------------------------------------------------------------------------------- |
| 400     | `INVALID_INPUT`  | `id` یک عدد صحیح مثبت نیست (مثلاً `abc`، `0`، `1.5`)، یا `status` ارسال نشده یا یکی از `TODO`، `DONE`، `EXPIRED` نیست |
| 404     | `TASK_NOT_FOUND` | وظیفه‌ای با این `id` وجود ندارد                                                                                       |
| 500     | `SERVER_ERROR`   | خطای غیرمنتظره                                                                                                        |

**نکته:** ابتدا `id` و سپس `status` اعتبارسنجی می‌شود و فقط در صورت معتبر بودن هر دو، وجود وظیفه بررسی می‌شود (پس `id` نامعتبر همیشه `400` است، نه `404`).

## چرخه‌ی وضعیت در فرانت‌اند

با کلیک روی برچسب وضعیت، فرانت‌اند وضعیت بعدی را در این چرخه می‌فرستد:

```
TODO  →  DONE  →  EXPIRED  →  TODO
```

## CORS

سرور فقط درخواست‌های مبدأ تعریف‌شده در متغیر `FRONTEND_URL` را می‌پذیرد (پیش‌فرض: `http://localhost:3000`). جزئیات در [03-integration-guide.md](./03-integration-guide.md).
